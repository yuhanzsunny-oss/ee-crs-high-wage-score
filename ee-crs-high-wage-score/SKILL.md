# EE 新政策算分(CRS + 高薪职业加分)

帮用户回答三类问题:**① 我现在/之后多少分 ② 新政策能给我加多少 ③ 材料要怎么备才站得住**。
规则细节、官方来源、"哪些是推断"在 `references/policy-rules.md`;分数线与池子数据在
`references/market-snapshot-2026-10.md`(带日期,会过期)。

## 工作流程

1. **先查用户自己的材料,再下结论。** 用户最反感"没看我的记录就否定我"。动手前先读:
   - 用户提供或指向的文件(offer、涨薪信、雇主信等)和已有的移民档案笔记;
   - 能读 PDF/图片就读(信头、职称、职责、起止日期、小时数、薪资)。
   缺的输入再问:年龄、学历、四项语言 CLB、加拿大/海外工作年数、加拿大学历、有无兄弟姐妹在加、岗位 NOC、offer 状态。
   一次问全,别挤牙膏。
2. **确定岗位档位。** `python scripts/crs_calc.py --lookup <NOC或关键词>`。
   不在表里就明说"该 NOC 不在 186 个高薪职业清单内,本政策加 0 分",并列出最接近、且**用户实际职责真能对上**的 NOC;
   不要为了加分建议用户套一个职责对不上的 NOC。
3. **用脚本算,不要心算。** 对话里手算出过 678/676、"170"、忽略 150 封顶等错误。
   ```
   python scripts/crs_calc.py --age 27 --edu bachelor --clb 9 --cdn-years 1 \
       --exp-noc 21231 --offer-noc 21231
   ```
   `--clb` 给 1 个值=四项相同,给 4 个值=听 读 写 说;`--edu` 取 secondary/1yr/2yr/bachelor/two_plus/master/phd;
   也可 `--json 档案.json`。输出含"有政策/无政策"两个总分和差值。多情景(英语提到 CLB9/10、满 1 年、过生日掉年龄分)就多跑几次做对比表。
   改过脚本先跑 `python scripts/test_crs_calc.py`,必须全 PASS。
4. **解释结果时区分两类:** 官方原文 / 官方没写。边界见 policy-rules.md。
   凡是涉及"怎么合成"的公式,先在官方 `changes.html` 找原文,别靠凑数字反推(本 skill 第一版就栽在这里,见 policy-rules.md 末尾)。
5. **材料建议只在事实基础上给**(见下方"合规红线")。

## 关键规则速记(完整版见 references)

- 劳动力市场融合因子(LMIF)= **两条路线自动取高,二选一**(官方:"not both"):
  工作经验路线 = 年限分(1年40…5年80)**+** 经验加分(Tier 1/2/3 = 70/40/20,需满12个月且该职业在清单上),最高 80+70=150;
  OFFER 路线 = 固定分 100/70/50,**不加在年限分上**。有清单职业的经验时,经验路线一定 ≥ offer 路线。
- 档位由**职业**的全国工资中位数决定,不是用户自己的工资。工资低不会让加分归零,只影响 offer 是否合理。
- Offer:全职、PR 后至少连续 1 年、不需要 LMIA、officer 判真实性。
- 单身脚本;带伴侣上限是 140 且表不同,脚本不支持,遇到要明说。
- 经验和 offer 的 NOC 要**分别问**:那份工作不在清单上就没有经验加分;脚本用 `--exp-noc` 和 `--offer-noc` 分别传,不做默认假设。
- 脚本只含法语加分的输入位(25/50),没有技工资格证组;遇到再手算并说明。

## 合规红线(用户的 PR 申请出错可能被禁入 5 年)

- 不编造、不美化职责、职称、时间;未核实的内容让用户自己确认。写雇主信草稿只用用户给的事实。
- 各份材料(offer、涨薪信、雇主信、纳税记录、兼职)职称/职责/日期必须自洽;同一份工作不重复报成两份。
  不一致时,让 HR 出变更说明,而不是两份矛盾的文件一起交。
- EE 系统里 offer 的 LMIA 占位字段,让中介或 IRCC 确认,不要替用户填。
- 告诉用户"加分不保证获邀";池子里的人多数也在加分,别说"政策必赢"。

## 沟通方式

- 用户讲中文,汇报、提问、总结一律中文;结论先行,数字用表。
- 用户说"你自己去查",就去查(官方页面/他的文件),不要把问题还给他。
- 被纠正的数字或事实,直接改并说明改了什么,别辩解。
- 政策页 2026-11-03 前后可能更新:回答"现在"的问题前,先重读 policy-rules.md 里的官方页面链接核对。

- `references/policy-rules.md` — 规则、来源、推断与未知项、常见算错点
